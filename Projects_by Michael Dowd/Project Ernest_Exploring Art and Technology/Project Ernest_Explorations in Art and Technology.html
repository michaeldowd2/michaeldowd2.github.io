Project Ernest is a painting machine, and the software that drives it. A digital image is processed, turned into brush strokes, and painted on a canvas up to 1m × 1m.

Objectives

  • Define a painting style in software, apply it to an image, and execute the result with a physical brush and paint.
  • Use the system to produce my own work.
  • Extend it with an iterative, agent-based layer that previews candidate paintings, scores them against a changing artistic preference, and over many cycles settles on styles the machine can paint.

How it works

The system is layered, with a one-way dependency. Image processing feeds stroke generation, which feeds a Python control layer, which drives the machine. Each stage can be changed without rewriting the ones below it.

  • Image processing — A modular, configurable stack of effects. The same stack can be applied to a new image to reproduce a painting style. Neural style transfer is one of the modules.
  • Vectoriser and stroke generation — The processed image is converted to vectors, then to brush paths. Brush contact is non-linear, so pressure builds as the brush meets the canvas in the way a painter applies it. Paths also rotate the brush, mix colour on a two-axis palette from a small set of base colours, and support mixing and scumbling on the canvas. Paint on the brush is tracked against the strokes so the system can estimate when more paint is needed.
  • Hardware control — A custom Python layer on GRBL turns those paths into motion commands. A UI visualises and tests the command stream before it is sent to the machine.
  • Machine — Built from CNC and 3D-printed parts, stepper motors, and two Arduinos running GRBL. The axes are X, Y, and Z, plus brush rotation and two palette axes. The painting area is 1m in each direction.
